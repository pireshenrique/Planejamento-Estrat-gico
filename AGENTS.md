# 3. REGRA MÁXIMA — FATOS E INTERPRETAÇÕES

É PROIBIDO inventar fatos.

Toda afirmação FACTUAL deve existir explicitamente em alguma camada real do projeto, como:

- dados estruturados;
- páginas estratégicas estruturadas;
- evidências cadastradas;
- relatórios;
- documentos;
- estudos;
- pesquisas;
- fontes associadas.

A IA PODE produzir:

- interpretações estratégicas;
- tendências;
- riscos potenciais;
- oportunidades potenciais;
- conexões estratégicas;
- possíveis implicações para a Lorenzetti;

desde que essas análises sejam DERIVADAS de fatos reais existentes no projeto.

Portanto:

FATO
→ precisa existir na base.

INTERPRETAÇÃO
→ pode ser construída pela IA a partir da combinação de fatos existentes.

IMPLICAÇÃO
→ pode ser inferida a partir de uma leitura fundamentada.

É proibido introduzir novos fatos para justificar uma interpretação.

---

# 4. DIFERENÇA ENTRE FATO, INTERPRETAÇÃO E IMPLICAÇÃO

## FATO / EVIDÊNCIA

Informação objetiva existente em:

- notícia;
- relatório;
- estudo;
- pesquisa;
- indicador;
- base estatística;
- legislação;
- documento institucional;
- dado estruturado do portal.

Exemplo:

> 82,0% das famílias estão endividadas.

Se esse dado existir na base e possuir origem rastreável, ele pode ser apresentado como fato.

---

## INTERPRETAÇÃO / ANÁLISE

Conclusão construída pela combinação de fatos existentes.

Exemplo:

> O nível elevado de endividamento, combinado com juros altos e maior planejamento das compras, sugere maior racionalidade na decisão de consumo.

Essa frase não precisa existir literalmente em uma fonte.

Entretanto, os fatos utilizados para construí-la precisam existir.

Utilizar preferencialmente expressões como:

- sugere;
- indica;
- aponta para;
- tende a;
- pode representar;
- há sinais de;
- pode estar associado a;
- pode contribuir para.

---

## IMPLICAÇÃO ESTRATÉGICA

Hipótese sobre possível consequência para a Lorenzetti.

Exemplo:

> Esse comportamento pode aumentar a relevância percebida de durabilidade, eficiência e custo total de uso.

Uma implicação jamais deve ser apresentada como fato comprovado.

# 8. IMPACTO PARA A LORENZETTI

Impactos para a Lorenzetti são hipóteses estratégicas.

Nunca utilizar linguagem categórica como:

- Gerará;
- Aumentará;
- Reduzirá;
- Exigirá;
- Resultará;
- Provocará.

Preferir:

- Pode gerar;
- Pode aumentar;
- Pode reduzir;
- Pode representar risco;
- Pode criar oportunidade;
- Pode favorecer;
- Pode demandar acompanhamento;
- Pode ampliar a relevância;
- Pode pressionar;
- Pode contribuir para.

Não inventar informações internas da Lorenzetti.

Não assumir, sem base:

- liderança;
- participação de mercado;
- capacidade produtiva;
- rentabilidade;
- estratégia atual;
- posicionamento competitivo;
- participação por categoria;
- estrutura industrial;
- desempenho financeiro.

---

# 9. RISCOS E OPORTUNIDADES

Riscos e oportunidades podem ser inferidos quando:

1. partirem de fatos reais;
2. estiverem associados a uma leitura fundamentada;
3. forem coerentes com os fatos utilizados;
4. não introduzirem novos fatos ou números;
5. forem escritos como hipóteses.

Exemplo:

FATO:
82% das famílias estão endividadas.

FATO:
80% dos consumidores planejam previamente suas compras.

INTERPRETAÇÃO:
Há sinais de maior racionalidade na decisão de compra.

HIPÓTESE:
Isso pode aumentar a importância de durabilidade e custo total de uso.

A hipótese não precisa existir literalmente na fonte.

Ela precisa ser coerente e rastreável aos fatos utilizados.

Não criar riscos ou oportunidades apenas para preencher uma seção.

---

# 10. TENDÊNCIAS

Uma tendência deve existir somente quando houver sustentação suficiente.

Preferencialmente:

- duas ou mais evidências/fatos independentes apontando para o mesmo movimento;

OU

- relatório relevante que caracterize explicitamente a tendência;

OU

- convergência entre fatos provenientes de páginas diferentes.

Um dado isolado pode permanecer como:

SINAL EM OBSERVAÇÃO.

Não existe obrigação de transformar todo conteúdo em tendência.

---

Nunca criar registros genéricos como:

- "Registro documental de evidência do portal";
- "Fonte Oficial Catalogada";
- "Evidência institucional";
- placeholders equivalentes.

# 13. ARQUITETURA DE DADOS — REGRA ESTRUTURAL OBRIGATÓRIA

As regras anteriores definem O QUE pode ser escrito.

As duas regras são igualmente importantes.

# 14. FONTE ÚNICA DE VERDADE

Todo dado factual atualizável deve existir em UM ÚNICO LUGAR.

Isso inclui:

- número;
- percentual;
- índice;
- valor monetário;
- série histórica;
- indicador.

O componente React nunca deve ser a fonte primária do valor.

ERRADO:

```tsx
<h3>47,9 pts</h3>
<p>O índice registrou 47,9 pontos em abril.</p>
```

CORRETO:

```ts
export const ICEI_DATA = {
  setor: {
    label: 'Setor Eletroeletrônico',
    value: 47.9,
    unit: 'pts',
    period: 'abril/2026',
    source: 'Abinee/Decon'
  }
}
```

Componente:

```tsx
<h3>{fmt(ICEI_DATA.setor.value)} pts</h3>
```

# 16. FORMATAÇÃO DE NÚMEROS

Sempre que possível, armazenar valores como números.

CORRETO:

```ts
value: 47.9
```

EVITAR:

```ts
value: '47,9 pts'
```

A formatação brasileira deve acontecer na apresentação.

Preservar:

* casas decimais;
* unidade;
* sinal;
* período;
* base comparativa.

---

# 17. SINAL DO VALOR

Nunca remover sinal negativo.

Exemplo:

-24,6%

deve ser:

```ts
value: -24.6
```

e não:

```ts
value: 24.6
```

---

# 18. PERÍODO DE REFERÊNCIA

Um número sem recorte temporal pode ser incompleto.

Incompleto:

> A produção caiu 4,3%.

Completo:

> A produção caiu 4,3% em maio/2026 frente a maio/2025.

Diferenciar:

* mês contra mês anterior;
* mês contra mesmo mês do ano anterior;
* acumulado no ano;
* acumulado em 12 meses;
* projeção;
* realizado;
* meta;
* cenário.



# 22. PLACEHOLDERS

```ts

```

Placeholder:

* não gera fatos;
* não entra em análise;
* não sustenta macrotendência;
* não conta como página analisável.

Nunca inventar conteúdo para transformar placeholder em analyzable.

# 30. ROTA ESTRATÉGICA VS ENTIDADE ANALÍTICA

Existem duas unidades distintas.

## ROTA ESTRATÉGICA

Subtema/página visível ao usuário.

## ENTIDADE ANALÍTICA

Objeto estruturado utilizado pela análise.

Uma rota pode possuir mais de uma entidade analítica.

Exemplo:

```text
eco-macro
→ eco-macro-pib
→ juros-selic
→ juros-real
→ eco-inflacao
→ eco-cambio
```

Nunca utilizar quantidade de entidades como sinônimo de quantidade de rotas.

---

# 31. PORTAL ROUTE ID

Cada entidade analítica deve possuir, quando aplicável:

```ts
portalRouteId
```

Exemplo:

```ts

  portalRouteId: 'eco-macro'
}
```

A cobertura do portal deve ser calculada por rota única.

# 32. COBERTURA DA BASE

Antes de gerar ou atualizar o Relatório Estratégico, auditar a cobertura.

Calcular dinamicamente:

## COBERTURA TOTAL

```text
rotas analyzable
/
total atual de rotas estratégicas
```

## COBERTURA DAS ROTAS COM CONTEÚDO

```text
rotas analyzable
/
(total atual de rotas - placeholders)
```

## COBERTURA DO REGISTRY

```text
rotas presentes no registry
/
total atual de rotas estratégicas
```

Nunca utilizar números históricos como denominador.

---

# 33. REGRA DE CONSISTÊNCIA DA COBERTURA

A soma deve obedecer:

```text
analyzable
+
placeholder
+
não estruturada
+
erro de integração
=
universo atual de rotas estratégicas
```

Se não fechar:

investigar.

Não corrigir silenciosamente.

# 87. PRINCÍPIOS FINAIS PERMANENTES

**Páginas do portal = conhecimento consolidado**

**Dados estruturados = fonte única de verdade**

**Evidências = sustentação factual**

**Fontes = rastreabilidade**

**Análises = interpretação**

**Implicações = hipóteses estratégicas**

**Relatório = síntese estratégica editorial**

**IA = ferramenta de organização, síntese e interpretação — nunca fonte dos fatos**

**A arquitetura técnica pode evoluir; os princípios permanecem.**

E principalmente:

**Nenhuma afirmação factual sem base rastreável.**

**Nenhuma leitura publicada apenas por parecer plausível.**

**Nenhuma alteração no relatório publicado sem solicitação explícita.**

**Nenhum número duplicado em múltiplas fontes de verdade.**

**Nenhuma afirmação de cobertura total sem comprovação.**

**Nenhum tema futuro deve ser excluído apenas porque ainda não existe no projeto atual.**

**Nunca tratar a estrutura atual como universo definitivo.**

**Sempre descobrir dinamicamente o universo atual do portal.**

**Preferir poucas leituras bem fundamentadas a muitas leituras genéricas.**
